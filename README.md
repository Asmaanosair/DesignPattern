Strategy Pattern
Used when you have multiple interchangeable behaviors (e.g., different payment methods) and want to switch between them easily at runtime without using if conditions.
Each behavior is implemented as a separate class that follows a common interface.

 Factory Pattern
Used to create object instances based on input without using if/else statements or knowing the exact class details.
The factory centralizes object creation logic, making the system cleaner and more scalable.

Adapter Pattern
Used when you need to integrate existing code with new code that has a different interface.
The adapter acts as a bridge, allowing incompatible interfaces to work together without modifying the original code.

 Decorator Pattern
Used to add new functionality (e.g., logging, notifications, validation) to existing objects dynamically without changing their structure.
This is done by wrapping the original object with another object that extends its behavior.
